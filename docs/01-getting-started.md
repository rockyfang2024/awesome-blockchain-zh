# 区块链与链上开发入门

这页帮助你建立后续开发学习所需的概念，不要求先持有加密资产。若已经会编程，可快速浏览概念，直接进入 [Solidity/EVM](02-solidity-path.md)、[Solana/Rust](03-solana-path.md) 或 [Bitcoin](04-bitcoin-path.md) 路径。

## 核心概念

| 概念 | 含义 | 开发时关注什么 |
|---|---|---|
| 区块与链 | 按协议规则组织并链接的数据 | 区块头、交易排序、确认与重组 |
| 哈希 | 将输入映射为固定长度摘要的函数 | 哈希用途取决于算法和协议，不等于加密 |
| 共识 | 节点对有效状态和区块顺序达成协议的机制 | PoW、PoS 的安全假设和最终性不同 |
| 节点 | 验证/转发网络数据并提供查询服务的软件实例 | 全节点、归档节点和 RPC 服务能力不同 |
| 交易 | 请求改变链上状态或转移价值的数据 | 签名、nonce、费用、执行结果和确认状态 |
| RPC | 应用与节点交互的接口 | RPC 服务可能限流、滞后或返回不完整数据 |
| 智能合约/程序 | 在特定链的执行环境中运行的代码 | 权限、状态、升级、测试和失败处理 |

不同链的账户模型和执行环境并不相同。EVM 常见账户/合约存储模型，Bitcoin 交易以 UTXO 为基础，Solana 程序围绕账户数据工作；不要直接把一种链的术语套用到另一种链。

## 钱包与密钥：仅需理解安全边界

钱包通常负责密钥管理、交易构造或签名界面；链上地址是公开标识，私钥或助记词能授权资产操作。开发者学习不需要创建或充值真实钱包：优先使用本地链、模拟器或测试网测试密钥。

- 助记词、私钥、Keystore 密码和 API token 不要粘贴到 Issue、聊天、网页或代码仓库。
- 硬件钱包能隔离部分密钥操作，但无法阻止用户确认恶意交易、错误地址或被欺骗的签名请求；不应宣称它能防住某个固定比例的攻击。
- 不要通过搜索广告或陌生私信下载钱包、连接站点或寻求“资产追回”。

## 交易费用与确认

链上操作可能需要费用，但费用单位、计算方式、出块节奏、确认和最终性机制因网络与负载而异。费用和耗时会随时间变化，教程中的数字不应视为当前报价或保证。查阅目标网络的官方文档和当前区块浏览器数据，并理解“交易已被打包”与“应用认为交易足够确定”可能是不同概念。

## 安全的动手顺序

1. 阅读目标生态的官方文档，确认网络、工具版本和账户模型。
2. 用本地开发链/模拟器编译并运行示例；EVM 可从 [Foundry](https://book.getfoundry.sh/) 或 [Hardhat](https://hardhat.org/docs) 开始。
3. 学会读取交易回执、事件、错误和合约状态；先写测试，再考虑部署。
4. 如确需测试网，使用独立的测试密钥和无价值测试币。不要把真实资产带入实验，也不要在未理解签名内容时批准交易。
5. 用目标链官方教程构建一个小项目，再进入对应的 [EVM](02-solidity-path.md)、[Solana](03-solana-path.md) 或 [Bitcoin](04-bitcoin-path.md) 专题。

测试网 faucet、钱包操作、第三方应用和 RPC 服务随时可能停运或改变。学习目标是理解交易和状态变化，不是完成真实资产 swap、借贷或 NFT 铸造。
